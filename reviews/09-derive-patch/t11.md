## Generic review

A code-review agent at medium effort read the whole change after T11:

- Fixed, and it reverses a T8 fix: the T8 review narrowed serde detection to `Serialize` or `serde::Serialize`, and then a re-exported or renamed derive (`my_prelude::Deserialize`, `serde_derive::Deserialize`) silently lost `#[serde(default)]`. Every missing key then read as `null` and cleared the field. Detection is back to the last path segment, as the Implementation Notes say. A same-named derive from another crate now fails to compile instead of losing data quietly. The README names both edges.
- Fixed: a generic non-`Option` field in a patch with serde derives did not compile (E0277), because `deserialize_with` stops serde from inferring `T: Deserialize`. Each such field now states `bound(deserialize = "T: <crate>::__private::Deserialize<'de>")`. Test: `generics_lifetimes_and_where_clauses_carry_over_with_serde_derives`, with a model whose only field is a `T`.
- Fixed: the release workflow would have tried to republish the hand-published first `presence-rs-derive` and stopped before `presence-rs`. It now publishes each crate unless the sparse index already lists that version, which also makes a rerun safe.
- Fixed: `tests/allocation.rs` did not list `src/patch.rs` and `src/__private.rs` among the files that must not use `alloc`.
- Fixed: the patch struct's doc used link syntax that showed up verbatim as a JSON Schema `description`. It is now plain text: "A partial update of a User."
- Fixed: `tests/release_tests.rs` compared manifest text. It now reads the pin from `cargo metadata`, and Miri skips it.
- Fixed: the README did not say that `JsonSchema` needs the `schemars` feature.
- Documented, not changed: with `#[serde(deny_unknown_fields)]` on the model, the patch rejects the keys of `#[patch(skip)]` fields. A client that sends back an immutable `id` gets an error. Whether to accept such keys silently instead is a design choice the spec does not make.
- Rejected: four trybuild builds, one per scenario-named test. The file lock serializes them, and the names map to scenarios.
- Checked and dropped: a README line claiming that a borrowed `&'a str` field does not deserialize in a serde patch. A scratch test showed that it does.

## Open

- The README's install snippets name version 0.3.0, which is already released without `derive`. They need the next version at the release bump.
- A model field of type `Presence<T>` maps to `Option<Presence<T>>`, which a JSON patch can never set to `Null` (see t8.md). Changing that needs a spec amendment.
