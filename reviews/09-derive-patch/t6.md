- Scenario to test mapping (`derive/tests/acceptance.rs`, model `renamed::Contact`):
  - The model's wire names are kept -> `the_models_wire_names_are_kept`
  - Unknown keys are rejected when the model rejects them -> `unknown_keys_are_rejected_when_the_model_rejects_them`
  - Fields skipped by serde are left out of the patch -> `fields_skipped_by_serde_are_left_out_of_the_patch`. A struct literal names only the two remaining fields, and applying the patch leaves the skipped ones alone.
  - A field with a custom serde codec is a compile error -> `a_field_with_a_custom_serde_codec_is_a_compile_error` (`tests/ui/serde_codec.rs`: four errors, one per codec. The `#[patch(skip)]` field with `with` gets none.)
- Red was genuine: the acceptance tests failed to compile (`missing fields cache and revision in ContactPatch`), and the unit tests failed to compile against the missing `container_serde` and `field_serde`.
- Copying `rename`, `alias`, `rename_all` and `deny_unknown_fields` happens only when the patch derives serde. Without a serde derive, a copied `#[serde]` attribute would not compile.
- The codec error and the `#[serde(skip)]` exclusion apply whether or not the patch derives serde, as decision 10 reads. A `#[patch(skip)]` field is never inspected.
- `#[serde(crate = "...")]` is not copied, since the spec lists only `rename_all` and `deny_unknown_fields`. A model that renames serde would need it on the patch too. This is left open for the user, and `crate` support would need a spec amendment.
